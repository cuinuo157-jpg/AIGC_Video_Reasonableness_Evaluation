## 评测流水线总览

```
evaluate.sh 执行顺序:

create_meta_info.py  →  PAS  →  OIS  →  TCS  →  CAS  →  MSS  →  calculate_score.py
                         │                                  ▲
                         └──────── perceptible_amplitude ────┘
                                   (MSS 依赖 PAS 结果)
```

所有维度共享 `meta_info.json` 作为中间数据载体，每个维度脚本读取后写入自己的分数字段，最终由 `calculate_score.py` 汇总为 CSV。

**最终得分**: 五个维度分数取均值 × 100，映射到 [0, 100] 区间。

## D1: PAS — 可感知运动幅度分数

**文件**: `perceptible_amplitude_score.py`
**全称**: Perceptible Amplitude Score
**目标**: 量化视频中主体对象的**实际可感知运动幅度**，剥离相机运动的干扰。

### 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│  输入: 视频 + subject_noun（来自 prompt 的主体名词）          │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1: Grounding DINO 目标检测                             │
│  在首帧中检测 subject_noun 对应的目标 → bbox                  │
└──────────────────────────┬──────────────────────────────────┘
                           │ boxes_filt
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2: SAM 语义分割                                        │
│  基于 bbox 提示 SAM 生成像素级 mask                           │
│  → subject_mask + background_mask                           │
└──────────────────────────┬──────────────────────────────────┘
                           │ masks
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3: CoTracker 稠密点跟踪                                │
│  分别对背景和主体区域进行跨帧关键点跟踪                        │
│  → pred_tracks [batch, frames, points, 2]                   │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 4: 运动幅度计算                                        │
│  calculate_motion_degree():                                 │
│    · 相邻帧关键点欧氏距离                                     │
│    · 除以视频对角线长度归一化                                  │
│    · 所有关键点平均 → motion_degree                           │
│  subject_motion = subject_degree - background_degree        │
└─────────────────────────────────────────────────────────────┘
```

### 核心算法: `calculate_motion_degree()`

```python
# 相邻帧关键点距离
distances = ||keypoints[:, t+1] - keypoints[:, t]||₂    # [batch, T-1, N_points]
# 对角线归一化
normalized = distances / sqrt(W² + H²)
# 时间维度求和 → 每个点的总运动量
total = sum(normalized, dim=time)                         # [batch, N_points]
# 所有点取均值
motion_amplitude = mean(total, dim=points)                # [batch]
```

### 关键设计决策

| 要素 | 选择 | 理由 |
|------|------|------|
| 分割模型 | Grounding DINO + SAM | 开集检测，适配任意 prompt 描述的主体 |
| 跟踪模型 | CoTracker (offline, window=60) | 稠密长程跟踪，覆盖全视频 |
| 归一化方式 | 视频对角线 | 分辨率无关的度量 |
| 运动解耦 | subject_degree - background_degree | 剥离相机平移/旋转的影响 |
| 未检测到主体 | 退化为 background_motion | 兜底策略 |

### 输出

- `perceptible_amplitude_score`: float，归一化运动幅度值（非 [0,1] 区间）
- 该值被 MSS 维度用作自适应阈值的依据

## D2: OIS — 物体完整性分数

**文件**: `object_integrity_score.py`
**全称**: Object Integrity Score
**目标**: 检测视频中人体结构是否存在**不合理变形**（肢体长度突变、关节角度突变）。

### 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│  输入: 视频                                                  │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1: RTMDet 人体检测                                     │
│  逐帧检测人体 bbox → NMS 过滤                                 │
└──────────────────────────┬──────────────────────────────────┘
                           │ bboxes
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2: RTMPose 关键点估计                                   │
│  Top-Down 范式: 基于 bbox 提取 17 个 COCO 人体关键点           │
│  → keypoints [17, 2] + scores [17]                          │
└──────────────────────────┬──────────────────────────────────┘
                           │ pred_instances_list
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3A: 肢体长度异常分析                                    │
│  analyze_lengths_over_time()                                │
│  · 计算 12 个身体部位的骨骼长度时序                             │
│  · 滑动窗口平均 + 相邻帧相对变化率                              │
│  · 变化率 > 45% → 标记为异常                                  │
│  → length_score = 正常部位数 / 总部位数                       │
├─────────────────────────────────────────────────────────────┤
│  Step 3B: 关节角度异常分析                                    │
│  analyze_joint_angles()                                     │
│  · 计算 8 个关节的三点角度时序                                 │
│  · 滑动窗口平均 + 相邻帧角度差                                 │
│  · 角度差 > 30° → 标记为异常                                  │
│  → angle_score = 正常关节数 / 总关节数                        │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  最终得分                                                    │
│  OIS = length_score × 0.5 + angle_score × 0.5              │
└─────────────────────────────────────────────────────────────┘
```

### 骨骼长度分析 — `analyze_lengths_over_time()`

**监测的 12 个身体部位**:

```
torso (5→11)          左右上臂 (5→7, 6→8)
左右前臂 (7→9, 8→10)  左右大腿 (11→13, 12→14)
左右小腿 (13→15, 14→16) 肩宽 (5→6)
髋宽 (11→12)          颈部 (0→5)
```

**异常判定逻辑**:
1. 过滤低置信度关键点（score > 0.3）
2. 滑动窗口平滑（默认 window=1）
3. 相邻窗口均值的**相对变化率** > 45% → 该部位异常
4. 有效测量不足一半帧数 → 视为正常（无法判定）

### 关节角度分析 — `analyze_joint_angles()`

**监测的 8 个关节**:

```
左右肘 (5-7-9, 6-8-10)     左右肩 (7-5-11, 8-6-12)
左右髋 (5-11-13, 6-12-14)  左右膝 (11-13-15, 12-14-16)
```

**异常判定逻辑**:
1. 三点构成角度的余弦计算
2. 滑动窗口平滑
3. 相邻窗口角度**绝对差** > 30° → 该关节异常
4. 有效测量不足 1/3 帧数 → 视为正常

### 关键设计决策

| 要素 | 选择 | 理由 |
|------|------|------|
| 检测模型 | RTMDet-m (COCO-Person) | 轻量高效的实时人体检测 |
| 姿态估计 | RTMPose-m (Body8, 256×192) | 17 点 COCO 格式，精度与速度平衡 |
| 异常度量 | 长度 + 角度双通道 | 互补性：长度捕捉缩放异常，角度捕捉弯折异常 |
| 置信度过滤 | score > 0.3 | 排除不可靠的关键点检测 |
| 评分粒度 | 按部位/关节独立评分 | 局部异常不影响全局分数 |

### 局限性

1. **仅支持人体**: 不适用于动物、车辆等其他主体
2. **单人假设**: `instances[0]` 只取第一个检测到的人
3. **2D 投影**: 3D 运动的投影可能导致长度/角度自然变化被误判

## D3: TCS — 时序连贯性分数

**文件**: `temporal_coherence_score.py`
**全称**: Temporal Coherence Score
**目标**: 检测视频中物体是否存在**不合理的凭空出现或消失**。

### 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│  输入: 视频 + subject_noun                                   │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 逐段检测与分割                                      │
│  每隔 step 帧（= FPS-1）：                                   │
│    Grounding DINO → 目标检测                                 │
│    SAM2 Image Predictor → 实例分割 mask                      │
└──────────────────────────┬──────────────────────────────────┘
                           │ 关键帧 mask
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2: SAM2 视频传播                                       │
│  将关键帧 mask 注入 SAM2 Video Predictor                     │
│  → 向后传播 step 帧，得到逐帧跟踪结果                         │
│  → 通过 IoU (>0.75) 关联跨段的同一物体                        │
└──────────────────────────┬──────────────────────────────────┘
                           │ tracking_result: List[Dict[obj_id → info]]
                           ▼
┌──────────────────────────┴──────────────────────────────────┐
│                                                             │
│  Step 3A: 消失检测                    Step 3B: 出现检测       │
│  get_disappear_objects()              get_appear_objects()   │
│  → 相邻采样帧之间消失的物体            → 相邻采样帧之间新增的物体│
│                                                             │
│  对每个消失/出现物体：                                        │
│  CoTracker 跟踪其 mask 区域的关键点                           │
│                                                             │
│  排除合理情况：                                               │
│  ├─ is_edge_vanish/emerge: 从画面边缘离开/进入                │
│  ├─ is_small_vanish/emerge: 因远离变小/从远处靠近              │
│  └─ is_detect_error: 检测误差（实际并未消失/出现）              │
│                                                             │
│  不满足以上任何合理解释 → 计为异常                              │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  最终得分                                                    │
│  vanish_score = (total_objects - abnormal_vanish) / total   │
│  emerge_score = (total_objects - abnormal_emerge) / total   │
│  TCS = (vanish_score + emerge_score) / 2                    │
└─────────────────────────────────────────────────────────────┘
```

### 合理消失/出现的判定规则

#### 边缘消失 `is_edge_vanish()`
- 物体不可见后，其跟踪点在后续帧中 ≥50% 超出画面边界 → 正常移出画面

#### 缩小消失 `is_small_vanish()`
- 物体跟踪点仍在画面内，但包围盒占画面比例 < 7% → 因远离而自然消失

#### 检测误差 `is_vanish_detect_error()`
- 反向跟踪后没有找到任何完全不可见的帧 → 可能是分割/检测的误差

#### 边缘出现 `is_edge_emerge()`
- 物体出现前，其反向跟踪点在之前帧中 ≥50% 超出画面边界 → 正常从画面外进入

#### 缩小出现 `is_small_emerge()`
- 物体出现前，其跟踪点形成的包围盒 < 3% → 从远处渐进出现

### 关键设计决策

| 要素 | 选择 | 理由 |
|------|------|------|
| 检测模型 | Grounding DINO (SwinB) | 开集检测，支持任意文本描述 |
| 分割模型 | SAM2 (hiera_large) | 视频级传播，跨帧一致性强 |
| 跟踪模型 | CoTracker (offline) | 提供可见性 (visibility) 信息，关键用于判定消失/出现 |
| 采样间隔 | FPS-1 帧 | 约 1 秒采样一次，平衡精度与效率 |
| 物体关联 | IoU > 0.75 | 跨段同一物体匹配 |
| 异常排除 | 三级排除（边缘/缩小/误差） | 避免将正常物理运动误判为异常 |

### 局限性

1. **计算开销极大**: 每个消失/出现物体都需要一次完整的 CoTracker 推理
2. **离散采样**: 仅在关键帧检测，可能遗漏快速出现又消失的物体
3. **遮挡不可区分**: 物体被遮挡后恢复可能被误判为"消失+出现"

## D4: CAS — 常识符合度分数

**文件**: `commonsense_adherence_score.py`
**全称**: Commonsense Adherence Score
**目标**: 评估视频中的动作是否符合**物理和行为常识**。

### 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│  输入: 视频 + meta_info.json                                 │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 构建评测数据集                                      │
│  从 meta_info.json 生成 test.csv (filepath + label=0)       │
│  构建 "Commonsense-Adherence" 数据集                         │
│  → VideoMAEv2 标准数据加载流程                                │
└──────────────────────────┬──────────────────────────────────┘
                           │ DataLoader
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2: VideoMAEv2 推理                                     │
│  模型: ViT-Giant (vit_giant_patch14_224)                    │
│  微调权重: vit_g_vmbench.pt (在 VMBench 标注数据上微调)        │
│  分类头: 5 类 (对应常识符合等级)                               │
│  输入: 16 帧 × 224×224                                      │
│  多段多裁剪推理: test_num_segment=10, test_num_crop=3        │
│  → 输出 5-class logits                                      │
└──────────────────────────┬──────────────────────────────────┘
                           │ logits per video
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3: 多段融合 + 分数计算                                  │
│  final_merge():                                             │
│  · 同一视频的多段结果取 softmax → 均值融合                     │
│  · 5-class 概率 × 权重 [0, 0.25, 0.5, 0.75, 1.0] 加权求和   │
│  → CAS ∈ [0, 1]                                            │
└─────────────────────────────────────────────────────────────┘
```

### 推理配置详解

| 参数 | 值 | 说明 |
|------|-----|------|
| 模型 | ViT-Giant (patch=14, input=224) | 12 亿参数级别的视频 Transformer |
| 帧采样 | 16 帧, sampling_rate=4 | 覆盖 64 帧跨度 |
| 测试增强 | 10 segments × 3 crops | 时间+空间多尺度推理 |
| 分布式 | DeepSpeed + torchrun | 支持多 GPU 并行推理 |
| 分类 | 5 级: [完全不符合, 较不符合, 一般, 较符合, 完全符合] | 映射到 [0, 0.25, 0.5, 0.75, 1.0] |

### 关键设计决策

| 要素 | 选择 | 理由 |
|------|------|------|
| 范式 | 端到端分类（非规则/启发式） | 常识难以硬编码，需学习隐式表征 |
| 骨干网络 | VideoMAEv2 ViT-G | 当前最强视频理解预训练模型之一 |
| 微调策略 | 在 VMBench 自建标注数据上 finetune | 领域适配 |
| 评分方式 | 概率加权而非 argmax | 保留分布信息，更细粒度 |
| 推理增强 | 10-segment × 3-crop | 减少随机采样偏差 |

### 局限性

1. **黑盒性强**: 无法解释"哪里不符合常识"
2. **依赖标注数据**: 模型表现取决于微调数据的质量和覆盖度
3. **计算最重**: ViT-G + 30 次推理/视频，需 DeepSpeed 分布式
4. **泛化边界**: 训练分布之外的罕见场景可能失效

## D5: MSS — 运动平滑度分数

**文件**: `motion_smoothness_score.py`
**全称**: Motion Smoothness Score
**目标**: 检测视频中是否存在**运动不平滑的伪影帧**（闪烁、抖动、突变）。

### 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│  输入: 视频 + perceptible_amplitude_score（来自 PAS）        │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 滑动窗口帧提取                                      │
│  load_video_sliding_window(video, window_size=3)            │
│  → 每帧为中心，取前后各 1 帧组成 3 帧片段                      │
│  → 边界填充: 复制首/尾帧                                     │
└──────────────────────────┬──────────────────────────────────┘
                           │ List[List[PIL.Image]]
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2: Q-Align 视觉质量评分                                │
│  QAlignVideoScorer (基于 mPLUG-Owl2)                        │
│  Prompt: "How would you rate the quality of this video?"    │
│  → softmax([excellent, good, fair, poor, bad])              │
│  → 加权 [1, 0.75, 0.5, 0.25, 0] → score ∈ [0,1]          │
└──────────────────────────┬──────────────────────────────────┘
                           │ scores: List[float]
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3: 自适应阈值                                          │
│  set_threshold(perceptible_amplitude_score):                │
│    < 0.1 → 0.01 | 0.1~0.3 → 0.015                         │
│    0.3~0.5 → 0.025 | ≥ 0.5 → 0.03                         │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 4: 异常帧检测                                          │
│  |score[i+1] - score[i]| > threshold → 标记 i 和 i+1 为异常  │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  MSS = 1 - len(artifact_frames) / len(total_frames)        │
└─────────────────────────────────────────────────────────────┘
```

### Q-Align 评分器核心

- **模型**: mPLUG-Owl2 多模态大模型
- **输入**: 滑动窗口内的多帧图像序列
- **预处理**: `expand2square()` 正方形填充（使用 image_mean 颜色）
- **输出**: 取最后 token 的 logits 在 5 个等级 token 上的分布
- **精度**: FP16 半精度推理

### 关键设计决策

| 要素 | 选择 | 理由 |
|------|------|------|
| 质量度量 | LMM (Q-Align) | 更接近人类感知，捕捉语义层面退化 |
| 时间建模 | 滑动窗口 + 差分检测 | 可解释，精确定位问题帧 |
| 异常判定 | 自适应阈值 | 适配不同运动强度场景 |
| 最终度量 | 正常帧占比 | 关注平滑性（波动）而非绝对质量 |

### 局限性

1. **计算开销大**: 每帧一次 LMM 推理
2. **阈值分档粗糙**: 仅 4 档硬编码
3. **窗口首帧处理**: 开头帧统一复制可能掩盖真实异常
4. **单一质量维度**: prompt 仅问"质量"，无法区分模糊/闪烁/形变

## 模型依赖汇总

| 模型 | 用途 | 使用维度 | 规模 |
|------|------|----------|------|

## 维度间依赖关系

```
PAS (独立)  ──────────────────────→  MSS (依赖 PAS 的运动幅度)
OIS (独立)
TCS (独立)
CAS (独立)
```

- **MSS → PAS**: MSS 使用 PAS 输出的 `perceptible_amplitude_score` 来设定质量波动阈值
- 其余四个维度之间无数据依赖，可并行执行

### 方法论分类

- **纯规则驱动**: PAS, OIS, TCS — 基于几何/物理规则的异常检测，可解释性强
- **纯学习驱动**: CAS — 端到端分类，依赖训练数据
- **混合驱动**: MSS — LMM 感知 + 规则化差分检测

### 技术路线总结

VMBench 的核心设计哲学是 **"用视觉基础模型提取中间表征，用启发式规则做异常判定"**：

1. **感知前端**: 利用 Grounding DINO / SAM / CoTracker / Q-Align 等 SOTA 基础模型提取高质量的中间表征（bbox、mask、轨迹、质量分数）
2. **规则后端**: 在中间表征上应用阈值/差分/排除规则进行异常判定
3. **例外**: CAS 因常识难以规则化，采用端到端学习方案

这种"强前端 + 轻后端"的设计在保持可解释性的同时，利用了基础模型的泛化能力。
