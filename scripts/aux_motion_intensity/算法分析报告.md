# aux_motion_intensity 算法分析报告

## 一、算法用途

### 1.1 核心功能

`aux_motion_intensity` 是一个**视频动态属性评估算法**，主要用于：

1. **量化视频的运动强度**：计算视频的整体动态度（0~1）
2. **场景类型分类**：自动判断视频是静态场景还是动态场景
3. **动态属性异常检测**：识别视频中不符合预期的动态表现
4. **辅助视频质量评估**：作为视频合理性评估的辅助指标（不计入总分）

### 1.2 应用场景

- **AIGC视频质量评估**：评估AI生成视频的动态合理性
- **视频异常检测**：检测视频中不自然的运动模式
- **场景理解**：理解视频场景的动态特征
- **视频分类**：根据动态程度对视频进行分类

## 二、可识别的视频外部表现异常

### 2.1 动态属性异常类型

算法可以识别以下视频外部表现异常：

#### 1. **静态场景异常**
- **表现**：应该是静态的场景出现了异常运动
- **检测指标**：
  - `mean_static_ratio > 0.5` 但 `mean_dynamics_score` 异常高
  - 静态区域占比高，但静态区域内的光流幅值异常

#### 2. **动态场景异常**
- **表现**：应该是动态的场景运动不足或过度
- **检测指标**：
  - `scene_type = "dynamic"` 但 `motion_intensity` 过低（< 0.15）
  - 或 `motion_intensity` 过高（> 0.85）但场景类型不匹配

#### 3. **运动不一致异常**
- **表现**：视频中不同区域的运动模式不一致
- **检测指标**：
  - `spatial_consistency_score` 过低（< 0.5）
  - `std_dynamics_score` 过高（时序变化过大）

#### 4. **相机运动异常**
- **表现**：相机运动补偿后仍存在异常残余运动
- **检测指标**：
  - `camera_factor` 异常（相机补偿失败率高）
  - 静态区域在补偿后仍有显著运动

#### 5. **时序不稳定异常**
- **表现**：视频的运动强度在时间上不稳定
- **检测指标**：
  - `temporal_stability` 过低（< 0.5）
  - `std_dynamics_score` 过大
  - `temporal_variation` 异常

#### 6. **空间覆盖异常**
- **表现**：运动区域覆盖不合理
- **检测指标**：
  - `spatial_coverage` 异常（运动区域占比不合理）
  - 静态区域占比与动态区域占比不匹配

### 2.2 具体异常表现示例

| 异常类型 | 视频外部表现 | 可能原因 |
|---------|------------|---------|
| **静态场景异常运动** | 静止物体出现抖动、闪烁 | 生成模型不稳定、后处理错误 |
| **动态场景运动不足** | 应该运动的物体静止 | 生成模型未正确理解运动 |
| **运动不连续** | 物体运动突然停止或跳跃 | 帧间生成不一致 |
| **相机抖动** | 整个画面不稳定晃动 | 相机运动补偿失败 |
| **局部异常运动** | 部分区域运动异常剧烈 | 局部生成错误 |
| **时序不一致** | 运动强度忽高忽低 | 生成模型时序建模失败 |

## 三、算法解决思路

### 3.1 整体架构

```
视频帧序列
    ↓
光流计算 (RAFT/Farneback/TV-L1)
    ↓
相机运动补偿 (可选)
    ↓
静态/动态区域检测
    ↓
多维度动态特征提取
    ↓
统一动态评分
    ↓
场景类型分类
    ↓
异常判定
```

### 3.2 核心解决思路

#### 思路1：光流基础的运动检测

**原理**：
- 使用光流（Optical Flow）计算相邻帧之间的像素运动
- 光流幅值反映运动强度，光流方向反映运动方向

**实现**：
- 支持多种光流算法：RAFT（深度学习）、Farneback（传统）、TV-L1（传统）
- 计算每对相邻帧的光流场

#### 思路2：相机运动补偿

**原理**：
- 使用单应性矩阵（Homography）估计相机运动
- 从原始光流中减去相机运动，得到物体运动

**实现**：
- 使用 SIFT/ORB 特征点匹配
- RANSAC 算法估计单应性矩阵
- 时序平滑处理，减少抖动

#### 思路3：静态/动态区域分离

**原理**：
- 基于光流幅值自动检测静态区域和动态区域
- 静态区域：光流幅值 < 阈值
- 动态区域：光流幅值 >= 阈值

**实现**：
- 形态学操作去除噪声
- 边缘检测优化静态区域边界
- 计算静态区域和动态区域的独立统计

#### 思路4：多维度特征融合

**原理**：
- 从多个维度评估视频动态属性
- 加权融合得到统一评分

**五个维度**：

1. **光流幅度（Flow Magnitude）** - 权重 0.35/0.45
   - 反映运动的绝对强度
   - 静态场景：使用静态区域动态分数
   - 动态场景：使用全局光流幅值

2. **空间覆盖（Spatial Coverage）** - 权重 0.25/0.30
   - 反映运动区域的空间占比
   - 计算：`1 - mean_static_ratio`

3. **时序变化（Temporal Variation）** - 权重 0.15/0.20
   - 反映运动强度在时间上的变化
   - 计算：`std_dynamics_score` 的 sigmoid 归一化

4. **空间一致性（Spatial Consistency）** - 权重 0.05
   - 反映不同区域运动的一致性
   - 计算：`1 - consistency_score`

5. **相机因子（Camera Factor）** - 权重 0.05/0.10
   - 反映相机运动补偿的效果
   - 计算：`1 - camera_compensation_success_rate`

#### 思路5：场景自适应评分

**原理**：
- 根据场景类型（静态/动态）调整权重
- 静态场景更关注静态区域的运动
- 动态场景更关注整体运动强度

**权重调整**：
- 静态场景：光流幅度权重更高（0.45），时序变化权重更低（0.10）
- 动态场景：光流幅度权重较高（0.45），时序变化权重较高（0.15）

#### 思路6：置信度评估

**原理**：
- 评估评分结果的可信度
- 基于时序稳定性和各维度一致性

**计算**：
```
confidence = 0.6 * temporal_stability + 0.4 * consistency
```

## 四、指标和判定标准

### 4.1 核心指标

#### 1. **统一动态度（motion_intensity）**

**定义**：视频整体运动强度的量化评分，范围 [0, 1]

**计算**：
```
motion_intensity = weighted_sum(component_scores)
```

**判定标准**：

| 动态度范围 | 等级 | 描述 | 典型示例 |
|-----------|------|------|---------|
| [0, 0.15) | 纯静态 | 几乎无运动 | 建筑物、雕塑、静止风景 |
| [0.15, 0.35) | 低动态 | 轻微运动 | 飘动的旗帜、缓慢移动的云 |
| [0.35, 0.65) | 中等动态 | 正常运动 | 行走的人、慢跑、日常活动 |
| [0.65, 0.85) | 高动态 | 剧烈运动 | 跑步、跳舞、体育运动 |
| [0.85, 1.0] | 极高动态 | 极剧烈运动 | 快速舞蹈、激烈运动、打斗 |

#### 2. **场景类型（scene_type）**

**定义**：视频场景类型分类

**判定标准**：
- **静态场景**：`mean_static_ratio > 0.5` 且相机补偿启用
- **动态场景**：`mean_static_ratio <= 0.5` 或相机补偿未启用

#### 3. **静态区域比例（mean_static_ratio）**

**定义**：静态区域占整个画面的比例

**判定标准**：
- **静态场景阈值**：> 0.5
- **动态场景阈值**：<= 0.5

#### 4. **时序稳定性（temporal_stability）**

**定义**：运动强度在时间上的稳定性

**计算**：
```
temporal_stability = 1 / (1 + std_dynamics_score)
```

**判定标准**：
- **稳定**：> 0.7
- **中等稳定**：0.4 ~ 0.7
- **不稳定**：< 0.4（异常）

#### 5. **空间一致性（spatial_consistency）**

**定义**：不同区域运动的一致性

**计算**：
```
consistency_score = 1 - (std(flow_magnitude) / mean(flow_magnitude))
spatial_consistency = 1 - consistency_score
```

**判定标准**：
- **一致**：> 0.7
- **中等一致**：0.4 ~ 0.7
- **不一致**：< 0.4（异常）

### 4.2 异常判定标准

#### 标准1：动态度与场景类型不匹配

**判定条件**：
```
IF scene_type == "static" AND motion_intensity > 0.35:
    异常：静态场景但动态度过高
ELIF scene_type == "dynamic" AND motion_intensity < 0.15:
    异常：动态场景但动态度过低
```

#### 标准2：时序不稳定

**判定条件**：
```
IF temporal_stability < 0.4:
    异常：运动强度在时间上不稳定
ELIF std_dynamics_score > threshold:
    异常：动态分数标准差过大
```

#### 标准3：空间不一致

**判定条件**：
```
IF spatial_consistency < 0.4:
    异常：不同区域运动模式不一致
ELIF consistency_score < 0.3:
    异常：光流幅值空间分布不一致
```

#### 标准4：相机补偿失败

**判定条件**：
```
IF camera_factor > 0.8:
    异常：相机运动补偿失败率高
ELIF camera_compensation_success_rate < 0.2:
    异常：相机运动估计失败
```

#### 标准5：静态区域异常运动

**判定条件**：
```
IF mean_static_ratio > 0.5 AND mean_dynamics_score > flow_mid_threshold:
    异常：静态区域占比高但仍有显著运动
```

#### 标准6：动态区域运动不足

**判定条件**：
```
IF mean_static_ratio < 0.3 AND mean_dynamic_magnitude < flow_low_threshold:
    异常：动态区域占比高但运动强度不足
```

### 4.3 综合异常评分

**异常严重程度分级**：

| 严重程度 | 判定条件 | 处理建议 |
|---------|---------|---------|
| **严重异常** | 多个维度同时异常 | 视频质量不合格 |
| **中等异常** | 1-2个维度异常 | 需要人工审核 |
| **轻微异常** | 单个维度轻微异常 | 可接受但需注意 |
| **正常** | 所有维度正常 | 视频质量合格 |

**异常评分计算**（示例）：
```python
anomaly_score = 0.0
if motion_intensity_mismatch:
    anomaly_score += 0.3
if temporal_instability:
    anomaly_score += 0.25
if spatial_inconsistency:
    anomaly_score += 0.25
if camera_compensation_failed:
    anomaly_score += 0.2

if anomaly_score > 0.5:
    status = "严重异常"
elif anomaly_score > 0.3:
    status = "中等异常"
elif anomaly_score > 0.1:
    status = "轻微异常"
else:
    status = "正常"
```

## 五、算法优势与局限

### 5.1 优势

1. **多维度评估**：从光流、空间、时序、一致性等多个维度综合评估
2. **场景自适应**：根据场景类型自动调整评估策略
3. **相机运动补偿**：能够区分相机运动和物体运动
4. **无需先验知识**：不需要知道视频内容，自动检测静态/动态区域
5. **可解释性强**：提供详细的组件分数和统计信息

### 5.2 局限

1. **不区分主体和背景**：第一版无法区分主体和背景，只能区分静态/动态区域
2. **依赖光流质量**：光流计算错误会影响所有后续分析
3. **阈值敏感性**：静态/动态区域检测依赖阈值设置
4. **计算复杂度**：RAFT 光流计算较慢
5. **对特定异常不敏感**：如物体突然消失、形状突变等

## 六、使用建议

### 6.1 参数调优

- **静态区域阈值**：`flow_threshold_ratio = 0.002`（归一化）或 `flow_threshold = 2.0`（未归一化）
- **相机补偿**：建议启用，特别是对于有相机运动的视频
- **光流算法**：RAFT 精度高但慢，Farneback 速度快但精度低

### 6.2 异常检测流程

1. **计算动态度和场景类型**
2. **检查动态度与场景类型是否匹配**
3. **检查时序稳定性**
4. **检查空间一致性**
5. **检查相机补偿效果**
6. **综合判定异常严重程度**

### 6.3 结果解读

- **motion_intensity**：主要指标，反映整体运动强度
- **scene_type**：场景类型，用于判断动态度是否合理
- **component_scores**：各维度分数，用于定位具体问题
- **temporal_stats**：详细统计信息，用于深入分析
- **confidence**：结果可信度，低置信度需要谨慎解读

## 八、总结

`aux_motion_intensity` 算法通过光流分析、相机运动补偿、静态/动态区域分离、多维度特征融合等技术，能够有效评估视频的动态属性，识别多种动态异常。算法设计合理，指标明确，适用于AIGC视频质量评估和异常检测场景。
